# Deploy the live demo

This directory runs the demo live at `https://wba-demo.noetis.dev` on one host
that already runs Caddy (hetzner2). It is separate from the local end-to-end
test in `e2e/`: real origins, Let's Encrypt certificates from the host's Caddy,
public roots only, and production cache and rotation values.

| File | What it is |
| :--- | :--- |
| `docker-compose.prod.yml` | The seller, the buyer, cfbot, and the runner. Agents listen on `127.0.0.1` only. |
| `Caddyfile.snippet` | The four site blocks to add to the host's `/etc/caddy/Caddyfile`. |
| `make-env.sh` | Writes the secrets file once, mode 600. |
| `localhost/` | A local rehearsal of this deployment (`make live-local`). Never deployed. |

## Host layout

The compose file finds everything relative to itself, so both checkouts sit
side by side, as they do on a laptop:

```text
/srv/wba-demo/
├── openproposal-web-bot-auth/   this repository
├── iab-agentic-primitives/      the library; the image build copies its src/
├── wba-demo.env                 the secrets (make-env.sh), mode 600
└── run/                         latest-run.json and history.json; the runner writes, Caddy reads
```

The checkouts hold no state: keys and SQLite databases live in Docker volumes,
and secrets and reports live outside both checkouts.

## Settings

The secrets file holds two values, both generated by `make-env.sh`:

| Variable | Used by | Purpose |
| :--- | :--- | :--- |
| `OPERATOR_KEY` | Seller, buyer, cfbot, runner | Every agent's own controls (`/operator/`, cfbot's `/run/`) require it in `X-Operator-Key`. The runner sends it. |
| `DEMO_BEARER_TOKEN` | Seller, buyer | The token the seller issues its bearer buyer. The seller stores only its SHA-256. |

You can override these Compose variables when you run `docker compose`:

| Variable | Default | Purpose |
| :--- | :--- | :--- |
| `WBA_LIB_DIR` | `../../iab-agentic-primitives` | The library checkout the image build copies |
| `WBA_ENV_FILE` | `../../wba-demo.env` | The secrets file |
| `WBA_RUN_DIR` | `../../run` | Where the runner writes its reports |
| `RUN_INTERVAL` | `900` | Seconds between runs |

`docker-compose.prod.yml` fixes everything else: the three origins
`https://seller.wba-demo.noetis.dev`, `https://buyer.wba-demo.noetis.dev`, and
`https://cfbot.wba-demo.noetis.dev`; a directory `Cache-Control: max-age` of
300 s; a verifier `max_cache_age` of 300 s; a rotation wait of 600 s; and a
signature lifetime of 300 s. No service sets `SSL_CERT_FILE` or
`NODE_EXTRA_CA_CERTS`, so the agents trust the image's public roots only, and
the seller's test-only fault toggle isn't mounted.

## Deploy

Run these steps in order. The host is `hetzner2`, and the commands that start
with `rsync` run on your laptop from the directory that holds both checkouts.

1.  In `README.md` and `site/index.html`, replace the placeholders
    `LIBRARY_URL` and `SPEC_URL` with the published links. To find them, run
    `grep -rn 'LIBRARY_URL\|SPEC_URL' README.md site/`.

2.  In Route 53, in the `noetis.dev` hosted zone, create four `A` records with
    a TTL of 300, each pointing at the host's public IPv4 address. On
    2026-11-07, `salesagent.noetis.dev` resolved to that address,
    `167.235.98.225`:

    | Name | Type | Value |
    | :--- | :--- | :--- |
    | `wba-demo.noetis.dev` | `A` | `167.235.98.225` |
    | `seller.wba-demo.noetis.dev` | `A` | `167.235.98.225` |
    | `buyer.wba-demo.noetis.dev` | `A` | `167.235.98.225` |
    | `cfbot.wba-demo.noetis.dev` | `A` | `167.235.98.225` |

    Add `AAAA` records only if the host's Caddy listens on IPv6. To confirm the
    records, run `dig +short A seller.wba-demo.noetis.dev`.

3.  Copy both checkouts to the host:

    ```bash
    ssh hetzner2 'mkdir -p /srv/wba-demo'
    rsync -av --delete --exclude .git --exclude .venv --exclude __pycache__ \
        --exclude .pytest_cache --exclude .ruff_cache --exclude node_modules \
        --exclude e2e/generated --exclude deploy/localhost/generated \
        openproposal-web-bot-auth/ hetzner2:/srv/wba-demo/openproposal-web-bot-auth/
    rsync -av --delete --exclude .git --exclude .venv --exclude __pycache__ \
        --exclude .pytest_cache --exclude .ruff_cache \
        iab-agentic-primitives/ hetzner2:/srv/wba-demo/iab-agentic-primitives/
    ```

    `--delete` is safe here: neither checkout holds secrets, keys, or reports.

4.  On the host, write the secrets and create the report directory. The runner
    runs as UID 10001, and Caddy reads the files it writes:

    ```bash
    /srv/wba-demo/openproposal-web-bot-auth/deploy/make-env.sh
    install -d -o 10001 -g 10001 -m 755 /srv/wba-demo/run
    ```

5.  On the host, build and start the three agents:

    ```bash
    cd /srv/wba-demo/openproposal-web-bot-auth
    docker compose -f deploy/docker-compose.prod.yml up --detach --build --wait seller buyer cfbot
    ```

6.  On the host, append the snippet to the Caddyfile, validate it, and reload
    Caddy. Caddy gets the four certificates from Let's Encrypt, which needs the
    DNS records from step 2:

    ```bash
    cat /srv/wba-demo/openproposal-web-bot-auth/deploy/Caddyfile.snippet >> /etc/caddy/Caddyfile
    caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
    systemctl reload caddy
    ```

7.  On the host, start the runner. It runs the flow at once, and then every
    15 minutes:

    ```bash
    docker compose -f deploy/docker-compose.prod.yml up --detach runner
    docker compose -f deploy/docker-compose.prod.yml logs runner
    ```

    The log line of a good run reads `<time> pass <ms> ms`.

8.  Check the deployment from your laptop:

    ```bash
    curl -si https://buyer.wba-demo.noetis.dev/.well-known/http-message-signatures-directory
    curl -s https://wba-demo.noetis.dev/latest-run.json | python3 -c 'import json,sys; print(json.load(sys.stdin)["ok"])'
    curl -s -o /dev/null -w '%{http_code}\n' -X POST https://buyer.wba-demo.noetis.dev/operator/keys   # 404
    ```

    Open `https://wba-demo.noetis.dev` and check that **Latest run** shows
    **Pass**.

## Update

Repeat step 3, and then rebuild and restart every service on the host:

```bash
docker compose -f deploy/docker-compose.prod.yml up --detach --build --wait
```

Keys and databases persist across rebuilds in the `wba-demo-live_*-data`
volumes. To change only the site, repeat step 3; Caddy serves the files
directly.

## Operate

- **Growth.** Each run issues two proposals and keeps their records and
  evidence: about 50 KB across both databases, or about 5 MB a day. To start
  over, run `down --volumes` as in [Tear down](#tear-down), and then step 5 and
  step 7. The agents mint new keys on the next start.
- **Firewall.** The agents and the runner reach each other's public names from
  inside Docker, so packets from the Docker bridge reach the host's public
  address on port 443. If a host firewall drops them, the directory steps fail
  with a connection error. Allow port 443 from the Docker bridge networks.
- **Rotate the buyer's key.** The keyring enforces production waits. On the
  host, with `OPERATOR_KEY` from `/srv/wba-demo/wba-demo.env`:

  ```bash
  key=$(sed -n 's/^OPERATOR_KEY=//p' /srv/wba-demo/wba-demo.env)
  curl -s -H "X-Operator-Key: $key" -X POST http://127.0.0.1:18082/operator/keys   # publish
  # 600 s later:
  curl -s -H "X-Operator-Key: $key" -X POST http://127.0.0.1:18082/operator/keys/NEW_KID/activate
  # 300 s after that:
  curl -s -H "X-Operator-Key: $key" -X DELETE http://127.0.0.1:18082/operator/keys/OLD_KID
  ```

## Rehearse locally

To run this compose file on a laptop, run `make live-local`. The override in
`localhost/` adds what stands in for public DNS and Let's Encrypt: a Caddy
container that serves `Caddyfile.snippet` with its upstreams pointed at the
containers, network aliases for the four names, and the e2e stack's throwaway
CA. The script runs the runner once and checks that the site serves a passing
`latest-run.json` and doesn't route the operator controls. With `KEEP=1`, the
stack stays up.

To validate the compose file alone, run `make live-config`.

## Tear down

The following steps remove the deployment. Steps 1 and 4 delete the agents'
keys, databases, secrets, and reports permanently.

1.  On the host, stop the stack and delete its volumes and images:

    ```bash
    cd /srv/wba-demo/openproposal-web-bot-auth
    docker compose -f deploy/docker-compose.prod.yml down --volumes --rmi all
    ```

2.  On the host, delete the four site blocks of the snippet from
    `/etc/caddy/Caddyfile`, and then run `caddy validate --config
    /etc/caddy/Caddyfile --adapter caddyfile` and `systemctl reload caddy`.

3.  In Route 53, delete the four `A` records.

4.  On the host, delete the files: `rm -r /srv/wba-demo` and
    `rm /var/log/caddy/wba-demo-access.log*`.
